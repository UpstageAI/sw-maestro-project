# [57조] 프로젝트 기획서 (v2)

## 소상공인 리뷰 응대 및 반복 불만 분석 AI Agent
> 리뷰를 정리하고, 답글을 쓰고, 개선점을 알려주는 사장님의 비서

**참여자**: 박세민, 박세원, 박준하, 유혁진, 윤성민

---

## 1. 문제 정의 및 프로젝트 개요

### ▸ 프로젝트 한 줄 정의 [필수]
소상공인이 매일 마주하는 고객 리뷰를 AI Agent가 자동으로 분석·분류·답변·요약해주고, 매장별 컨텍스트(메뉴·과거 응대·반복 불만)를 기억해 점점 더 개인화되는 리뷰 운영 자동화 데모 프로젝트.

### ▸ 서비스 한 줄 정의 [필수]
> "리뷰 붙여넣기 한 번이면, 답글 초안과 반복 불만 TOP 3, 개선 체크리스트까지 정리해주는 AI 사장님 비서. 쓸수록 우리 가게 톤과 메뉴를 학습한다."

### ▸ 서비스 선정 배경 [권장]
- 소상공인은 하루에도 수십 개의 리뷰가 쌓이지만, 답글을 일일이 작성할 시간과 멘탈이 부족하다.
- 부정 리뷰가 와도 '무엇이 반복되는 불만인지'를 데이터로 잡아내기 어려워, 같은 불만이 여러 번 쌓여도 개선으로 이어지지 못한다.
- 기존 리뷰 관리 SaaS는 가격 부담이 크고, 단순 답글 자동화에 그쳐 '분석 → 개선' 사이클을 만들어주지 못한다.
- AI 서비스에 익숙하지 않은 사장님도 부담 없이 쓸 수 있는, '붙여넣기 한 번'으로 끝나는 가벼운 도구가 필요하다.
- LLM의 분류·요약·작성 능력을 잘 묶고, 매장별 누적 컨텍스트(메뉴·과거 응대 톤)를 입혀 1인 비서급 Agent를 가볍게 만들 수 있다.

### ▸ 해결하려는 문제 [필수]
- **문제 1. 답글 작성 부담**: 매일 들어오는 리뷰에 일일이 정중한 답글을 다는 것은 시간·감정 노동 모두 부담이 크다. 특히 부정 리뷰 답변은 더 까다롭다.
- **문제 2. 반복 불만 가시화 실패**: '대기시간 길다', '직원 응대', '위생' 같은 비슷한 불만이 반복돼도, 단일 세션·개별 리뷰 단위로만 보면 패턴이 보이지 않는다. 여러 세션·여러 주에 걸친 누적 분석이 필요하다.
- **문제 3. 개선 액션 부재**: 리뷰는 쌓이는데, 그래서 무엇을 바꿔야 하는지 구체적인 To-Do로 연결되지 않는다. 데이터가 행동으로 이어지지 않는다.
- **문제 4. 사장마다 다른 응대 스타일·메뉴 컨텍스트 미반영**: 같은 '맛없다' 리뷰여도 매장의 시그니처 메뉴, 가격대, 평소 응대 톤에 따라 답변이 달라야 한다. 일반화된 LLM 답글은 '내 가게 같지 않다'는 위화감을 준다.

### ▸ 대상 사용자 [필수]
- **1차 타깃**: 카페·음식점·베이커리·디저트·소형 외식 매장의 1인 사장 또는 소규모 운영팀.
- **2차 타깃**: 네이버 플레이스·배달의민족·쿠팡이츠 등에서 월 50건 이상 리뷰가 쌓이는 매장.
- **핵심 가정**: AI 서비스에 익숙하지 않은 사장님 — 챗GPT를 한두 번 써본 정도 또는 처음 쓰는 분도 첫 화면에서 무엇을 해야 하는지 바로 알 수 있어야 한다.
- **사용 환경**: PC 또는 태블릿에서 마감 후 10~15분간 리뷰 운영 시간을 갖는 사장님.

### ▸ 핵심 가치 [필수]
**'리뷰 운영 시간을 30분 → 5분으로 줄여주는 것.'**

이 서비스가 가장 잘해야 하는 단 하나는, 사장님이 리뷰를 "읽기-답글쓰기-개선아이디어 떠올리기"까지 직접 다 하지 않아도 되도록, AI가 1차 가공해서 검토만 하면 끝나는 상태로 만들어주는 것이다.

**부가 가치 — 쓸수록 똑똑해지는 비서**: 매장 메뉴·과거 응대·누적 불만이 컨텍스트로 쌓이며, 분류와 답글이 점점 더 '우리 가게답게' 개인화된다.

## 2. 사용자 및 Agent 설계

### ▸ 타깃 사용자 페르소나 [권장]
**페르소나: 김사장 (38세, 동네 카페 1인 운영)**
- 평일 오전 8시~오후 8시 매장 운영, 마감 후 30분 정도 짬으로 리뷰를 본다.
- 네이버 플레이스 리뷰가 주 5~15건 쌓임. 부정 리뷰 1~2건이 마음에 걸려 답글을 미루다가 까먹는다.
- 디지털 도구는 카카오톡·네이버 스마트플레이스 정도만 능숙. 'AI 서비스'라고 하면 살짝 두렵고, 회원가입·설정이 많으면 바로 이탈.
- '잘 정리된 한 화면'과 '복사해서 바로 쓸 수 있는 답글'을 가장 좋아함.

### ▸ Agent의 역할 [필수]
**3-in-1 리뷰 운영 비서 + 매장 컨텍스트 학습자**

- **분석가 역할**: 입력된 리뷰의 감정(긍정/부정/중립)을 판단하고, 5대 카테고리(맛, 서비스, 가격, 대기시간, 위생) 중 어디에 해당하는지 분류. 매장이 등록한 메뉴·시그니처를 알고 있을 경우 분류 결과에 메뉴명을 함께 태깅.
- **작성자 역할**: 가게 톤앤매너에 맞춰 답글 초안을 생성. 사장이 과거에 채택했던 답글 샘플을 few-shot으로 활용해 '평소 우리 가게가 답하던 방식'을 모사.
- **컨설턴트 역할**: 단일 세션이 아니라 누적된 여러 세션·여러 주의 리뷰에서 반복 불만 TOP 3를 뽑고, "이번 주 이걸 점검해보세요" 형식의 개선 체크리스트를 제공.
- **학습자 역할**: 사장이 답글을 수정하거나 분류 라벨을 고치면, 그 피드백을 다음 분석/답글에 반영(가벼운 선호 학습).

### ▸ Agent의 성격 및 톤앤매너 [권장]
- **기본 성격**: 차분하고 정중한 비서. 사장님을 평가하지 않고, 사실 위주로 정리해줌.
- **답글 톤**: 사장이 선택 가능 (정중체 / 친근체 / 격식체). 기본값은 '정중체'. 사장이 과거에 직접 작성한 답글 샘플이 있으면 해당 톤을 우선 학습.
- **UI 메시지**: 짧고 단정한 문장. 감탄사·과장 표현 사용 금지. 한국어 존댓말 고정.
- AI 친숙도가 낮은 사장 대상이라는 점을 의식해, 모든 안내는 '버튼 한 개 = 한 행동' 원칙으로 단순화.

### ▸ Agent의 자율성 범위 [필수]
**'분석·요약·초안'까지는 자동, '발행·외부 액션'은 절대 안 함.**

- **자동 수행**: 리뷰 분류, 답글 초안 생성, 반복 불만 요약, 개선 체크리스트 작성, 누적 리뷰 통계 갱신, 매장 컨텍스트(메뉴·톤 샘플) 갱신.
- **사람 개입 필수**: 답글 최종 발행, 매장 정책 변경, 외부 플랫폼 게시. Agent는 '초안'과 '제안'까지만.
- **안전장치**: 욕설·법적 위험 표현이 포함된 답글 후보는 자동 보류하고 사장에게 경고.

## 3. 핵심 기능 및 사용자 흐름

### ▸ 주요 사용자 시나리오 [필수]

**시나리오 A. 마감 후 리뷰 정리 (단건/소량 붙여넣기)**
저녁 9시, 김사장은 마감 후 화면에 그날 들어온 리뷰 8건을 그대로 복사해 텍스트 박스에 붙여넣는다. 회원가입·설정 없이 '분석 시작' 한 번으로 끝. Agent가 30초 안에 "부정 2건, 중립 1건, 긍정 5건 / 대기시간 불만 2건"으로 정리해주고, 부정 리뷰 2건에는 정중한 답글 초안을 자동 생성한다. 사장은 답글을 살짝 다듬어 복사 → 네이버 플레이스에 붙여넣고 마감.

**시나리오 B. 주말 회고 (누적·다세션 분석)**
일요일 밤, 사장은 한 주치 리뷰 50건을 한 번에 붙여넣는다. Agent는 이번 입력뿐 아니라 지난 4주간 누적된 리뷰까지 함께 보고 '최근 4주 반복 불만 TOP 3 = 대기시간(누적 38회) / 빨대 위생(11회) / 키오스크 어려움(9회)'을 뽑아준다. 다음 주 점검 체크리스트('피크타임 인력 1명 추가 검토' 등)도 함께 제공.

**시나리오 C. 매장 컨텍스트 등록 (최초 1회 + 수시 추가)**
처음 사용 시, 사장은 가게명·업종·대표 메뉴 5~10개·평소 답글 샘플 3개를 한 화면에서 입력한다. 이후 모든 분석/답글은 이 컨텍스트를 자동 주입해서 생성된다. 사장이 답글을 수정하면 수정본이 톤 샘플 풀에 추가된다.

### ▸ 핵심 기능 정의 [필수]

| 번호 | 기능 | 설명 |
|---|---|---|
| F1 | 리뷰 입력 (붙여넣기 우선) | AI 사용 경험이 적은 사장님을 위한 단일 텍스트 박스 + '분석 시작' 버튼. 리뷰를 한 건씩 또는 여러 건을 그대로 붙여넣기 가능. CSV 업로드는 보조 옵션. |
| F2 | 감정 분석 | 각 리뷰를 긍정/부정/중립으로 자동 분류하고 신뢰도 점수를 함께 보여준다. |
| F3 | 유형 분류 | 맛 / 서비스 / 가격 / 대기시간 / 위생 5대 카테고리로 멀티라벨 분류. 매장 메뉴 컨텍스트가 있으면 해당 메뉴명도 자동 태깅. |
| F4 | 답글 초안 생성 (개인화) | 감정·유형·매장 톤·과거 사장 답글 샘플을 반영해 한국어 답글 초안 1~2개 생성. 복사 버튼 제공. |
| F5 | 반복 불만 TOP 3 (다세션) | 현재 입력 + 누적 세션의 리뷰를 함께 보고 빈도 높은 부정 카테고리·키워드를 자동 집계. |
| F6 | 개선 체크리스트 | TOP 3 기반으로 '이번 주 점검 항목' 3~5개를 To-Do 형태로 출력. |
| F7 | 매장 컨텍스트 관리 (신규) | 메뉴/시그니처/가격대/평소 답글 톤 샘플을 저장·수정. 모든 Agent 호출 시 자동 주입. |
| F8 | 사장 피드백 반영 (신규) | 답글 수정·라벨 정정 이력을 누적해 다음 호출의 few-shot으로 사용. |

### ▸ 사용자 관점 워크플로우 [필수]
1. **(최초 1회)** 매장 정보 입력 — 가게명, 업종, 대표 메뉴, 답글 톤 선택, 평소 답글 샘플 3개
2. 리뷰 텍스트 박스에 붙여넣기 (회원가입·설정 추가 단계 없음)
3. '분석 시작' 클릭
4. 결과 화면 한 페이지에서 (a) 감정/유형 라벨, (b) 답글 초안, (c) 반복 불만 TOP 3, (d) 개선 체크리스트 동시 확인
5. 답글 복사 또는 체크리스트 다운로드, 필요 시 답글 수정 → 시스템이 톤 샘플로 학습

### ▸ 시스템 관점 워크플로우 [권장]
```
[Input Parser]
  → [Context Loader (매장·과거 응대·메뉴)]
  → [Sentiment & Category Classifier Agent]
  → [Reply Drafter Agent]
  → [Pattern Aggregator (다세션)]
  → [Checklist Generator]
  → [UI Renderer]
```
- 누적 데이터는 SQLite에 (가게ID, 리뷰원문, 라벨, 답글원본, 답글수정본, 타임스탬프, 세션ID) 형태로 저장.
- Pattern Aggregator는 누적 리뷰 N건 이상일 때 자동 활성화, 그 이하면 단건 분석 결과만 출력.
- Context Loader는 매장 메타·과거 답글 샘플·최근 N개월 분류 통계를 자동으로 prompt에 주입.

## 4. 기술 구현 설계

### ▸ 기술 스택 [필수]

| 영역 | 선택 |
|---|---|
| 언어/런타임 | Python 3.11 |
| Agent 프레임워크 | LangGraph (멀티 Agent 라우팅) + LangChain 보조 |
| LLM (1순위) | Claude Sonnet 4.6 — 한국어 품질·지시 따르기 우선 |
| LLM (대안) | OpenAI gpt-5.x-mini — 비용·지연 최적화 시 사용 |
| LLM (검토) | Qwen 등 오픈소스 — 로컬/온프레미스·비용 추가 절감 시 옵션 |
| UI | Streamlit (단일 페이지, 빠른 구현, 붙여넣기 플로우 친화) |
| 저장소 | SQLite (로컬 파일 DB) + 매장 컨텍스트 테이블 |
| 패키징 | uv + Makefile, 단일 명령(`make run`)으로 로컬 실행 |
| 테스트 | pytest + 샘플 리뷰 50건 골든셋 + 모델별 A/B 비교 노트 |

> **모델 선택 기준**: (1) 골든셋 50건 분류 정확도, (2) 1,000건 처리 시 추정 비용, (3) 평균 응답 지연. 세 모델을 동일 프롬프트로 돌려 점수표를 만들고 1순위를 결정한다.

### ▸ 시스템 아키텍처 [권장]
**Multi-Agent 구조 (LangGraph 노드 기준)**

```
[UI: Streamlit]
    ↓ 리뷰 텍스트, 매장 메타정보
[Orchestrator (LangGraph)]
    ├─ ContextLoader     → 매장 컨텍스트(메뉴·톤 샘플·최근 통계) 주입
    ├─ ClassifierAgent   → 감정 + 5대 카테고리 + (선택)메뉴 라벨 (JSON)
    ├─ ReplyDrafterAgent → 매장 톤·과거 응대 샘플 반영 답글 초안 1~2개
    ├─ PatternAgent      → 현재 + 누적 라벨 집계, 다세션 TOP 3 추출
    └─ ChecklistAgent    → TOP 3 → 점검 항목 3~5개
                      ↓
[SQLite] ← 누적 리뷰/라벨/답글이력/매장 컨텍스트 저장
```

### ▸ 프롬프트 설계 전략 [권장]
- 모든 Agent는 **'역할 / 입력 스키마 / 출력 스키마(JSON) / 금지사항'** 4단 구조 시스템 프롬프트 사용.
- **ClassifierAgent**: few-shot 5건(긍정·부정·중립·복합·이모지 포함) 고정 + 매장 메뉴 리스트 주입, 출력은 strict JSON.
- **ReplyDrafterAgent**: 매장 톤(정중/친근/격식)과 부정 리뷰 시 '사과 → 사실 인정 → 개선 약속' 3단 골격 강제. 사장이 과거에 채택한 답글 샘플 2~3개를 few-shot으로 동적 주입.
- **ChecklistAgent**: 반드시 동사로 시작하는 To-Do 문장만 생성하도록 출력 형식 제약.
- 모든 출력은 한국어 존댓말 고정, 가격/할인 약속 등 매장 정책에 영향을 주는 표현은 자동 회피.

### ▸ 데이터 활용 및 기억 관리 [권장] — 강화
**핵심 원칙**: 반복되는 불만은 단일 세션이 아닌 '여러 세션·여러 주' 단위로 봐야 한다. 따라서 메모리 계층을 단/중/장기로 나눈다.

- **단기 메모리**: 현재 입력된 리뷰 배치 내에서만 유지(LangGraph state).
- **중기 메모리(세션 누적)**: 최근 4주(설정 가능) 리뷰·라벨·답글이력을 윈도우로 PatternAgent에 주입. 다세션 반복 불만 탐지에 사용.
- **장기 메모리(매장 컨텍스트)**: SQLite에 (가게ID, 리뷰, 감정, 카테고리, 메뉴태그, 생성된 답글, 사장이 수정한 답글, 타임스탬프, 세션ID) 저장. 가게별 누적 통계가 PatternAgent의 입력.
- **매장 프로필 테이블(신규)**: 상호, 업종, 대표 메뉴 5~10개, 가격대, 답글 톤 옵션, 평소 답글 샘플 3개. 모든 Agent 호출 시 ContextLoader가 자동 주입.
- **개인화 학습**: 사장이 답글을 수정하거나 라벨을 정정하면, 그 차이를 '톤 샘플 풀'과 '분류 보정 힌트'에 반영해 다음 호출에 사용.
- **개인정보**: 리뷰 본문 외 사용자 닉네임·전화번호는 입력 단계에서 정규식으로 마스킹.

### ▸ (옵션) 외부 정보 활용 및 RAG 활용 영역 [옵션 — 본 범위에선 설계만]
실제 구현은 옵션으로 두되, 확장 시 적용 지점을 미리 정의한다.

- **Web Search (옵션)**: 누적 불만 카테고리에 맞춰 외부 정보를 가져와 새로운 To-Do/제안을 생성. 예) '대기시간' 불만이 4주 연속 1위 → 동종업계 피크타임 운영 팁·키오스크 사례를 검색해 체크리스트에 추가 항목 제안.
- **RAG 활용 후보 1 — 매장 자체 지식**: 누적된 답글이력·메뉴 설명·이전 컴플레인 처리 사례를 벡터화해 ReplyDrafterAgent가 유사 케이스를 검색·인용.
- **RAG 활용 후보 2 — 외부 가이드**: 식약처 위생 가이드, 노동법상 응대 매뉴얼 등 공신력 있는 문서를 인덱싱해 ChecklistAgent의 근거로 사용.
- **MVP 범위에는 포함하지 않음**: 위 두 기능은 '확장 로드맵'에 명시하고, 데모에서는 인터페이스 자리(빈 카드)만 노출.

### ▸ 제약사항 및 예외 처리 [필수]

**이번 범위에서 제외하는 것**
- 네이버 플레이스·배달앱 직접 연동(크롤링/API). 리뷰 입력은 텍스트 붙여넣기·CSV 업로드만.
- 답글 자동 발행. Agent는 초안 제공까지만, 최종 발행은 사람이 한다.
- 한국어 외 언어. 영문·외국어 리뷰는 '지원 외' 라벨 후 분석 제외.
- Web Search 및 RAG 기반 외부 지식 활용은 옵션 — 인터페이스만 정의, 실제 호출은 데모 범위에서 제외.

**주요 예외 처리**
- 빈 리뷰·중복 리뷰 자동 필터링.
- LLM 응답이 JSON 파싱 실패 시 1회 재시도 → 실패 시 해당 리뷰만 '분석 실패'로 표시하고 다음 리뷰 진행.
- 욕설·법적 위험 표현이 답글 초안에 포함되면 출력 보류 + 경고 메시지.
- 누적 리뷰 10건 미만이면 PatternAgent·ChecklistAgent는 자동 비활성화.
- 매장 컨텍스트 미입력 상태에서도 기본 분석은 동작, 단 '컨텍스트를 입력하면 더 우리 가게답게 답글이 나옵니다' 안내.

### ▸ MVP 범위 [필수]

**반드시 만든다 (In-scope)**
- F1 리뷰 입력(붙여넣기 우선) · F2 감정 분석 · F3 유형 분류
- F4 답글 초안 생성 (정중체 기본 + 친근/격식 옵션, 매장 톤 샘플 반영)
- F5 다세션 반복 불만 TOP 3 · F6 개선 체크리스트
- F7 매장 컨텍스트 관리(메뉴·톤 샘플) · F8 사장 피드백 반영(수정 답글 누적)
- Streamlit 단일 페이지 UI · SQLite 누적 저장 · 로컬 1-command 실행
- LLM 3종(Sonnet 4.6 / gpt-5.x-mini / Qwen) 골든셋 비교 노트

**이번에는 안 한다 (Out-of-scope)**
- 외부 플랫폼 API 연동, 모바일 앱, 다국어 지원, 사장 인증/회원 시스템, 클라우드 배포.
- Web Search 기반 자동 외부 정보 수집 · RAG 기반 외부 가이드 인용 — 설계만 명시, 구현은 옵션.

### ▸ 기대 효과 [권장]
- **사장님 관점**: 리뷰 운영 시간이 '하루 30분' → '하루 5분'으로 줄어드는 체감. 부정 리뷰에 대한 답글 부담 완화. AI 익숙도와 무관하게 '붙여넣기 한 번'으로 사용 가능.
- **매장 운영 관점**: 다세션 반복 불만이 가시화되면서 "느낌" 대신 "데이터"로 의사결정 가능. 같은 불만이 4주 연속 TOP에 오르면 자동 알림.
- **학습/포트폴리오 관점**: 멀티 Agent 라우팅, JSON-strict 프롬프트, 매장별 컨텍스트 주입과 다세션 메모리, 사장 피드백 반영 루프, 모델 비교 평가까지 한 번에 경험.
- **확장 관점**: 동일한 구조로 '병원 후기', '학원 만족도', 'B2B 고객 VOC'로 도메인 확장 가능. Web Search·RAG는 확장 단계에서 자연스럽게 결합.
