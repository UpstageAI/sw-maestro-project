# FE-028 - Report empty/loading/error state

## 목표
Daily Report 화면의 로딩, 빈 결과, 에러 상태를 모두 명시적으로 처리한다.

## 사전 조건
- 같은 트랙 선행 step: FE-027 완료.
- mockable 외부 의존성: BE-017, AI-022. 미완료 상태에서도 MSW 또는 fixture로 진행한다.
- hard 외부 의존성 없음.

## Prototype 기준
- 1차 기준: `prototype/index.html`의 `.app-page[data-page="report"]`.
- 확정 변형 기준: `prototype/report-variations.jsx`의 `VariantCPlus`.
- 스타일 기준: `prototype/styles.css`의 report page shell, card, button, empty/loading 상태에 재사용되는 token.
- 보조 색인: `docs/design.md` §4.7, §5.1, §5.2. 충돌 시 원본 prototype을 따른다.
- 로딩, 준비 전, 에러 상태도 report 화면의 phone-frame, spacing, card tone을 유지한다.

## 테스트 명세
- **테스트 파일**: `frontend/src/pages/DailyReportPage.test.tsx`
- **테스트 이름**: `daily_report_page_shows_not_ready_state_for_404`
- **fixture**: MSW `GET /api/report/2026-05-13`가 404 `{code:"REPORT_NOT_READY", date:"2026-05-13"}`를 반환한다.
- **action**: `/report/2026-05-13`으로 렌더링한다.
- **assertions**:
  - role `alert`가 보인다.
  - 텍스트 `아직 리포트가 준비되지 않았어요`가 보인다.
  - link role 이름 `피드로 돌아가기`가 보인다.
- **mock strategy**: MSW delay와 error handler를 사용한다. 실제 서버는 호출하지 않는다.
- **out of scope**: retry polling은 구현하지 않는다.

## 구현 기준
- loading state에는 role `status` 이름 `리포트 불러오는 중`을 둔다.
- 500 error는 `리포트를 불러오지 못했어요` 문구를 사용한다.

`cd frontend; pnpm lint`

- /report/2026-05-13에서 준비 전 alert와 피드 복귀 link가 보인다.
- prototype report 화면과 구현 화면을 나란히 비교한다.
- empty/loading/error 상태가 report page의 phone-frame, spacing, card radius, button style을 유지한다.
