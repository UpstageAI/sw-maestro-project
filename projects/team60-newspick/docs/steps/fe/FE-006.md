## 테스트 명세

- **테스트 파일**: `frontend/__tests__/sse.test.ts`
- **테스트 이름**: `subscribe_sse_dispatches_named_events_and_closes_on_done`
- **given**: fake `EventSource`가 `step`, `done` 이벤트를 발생시킬 수 있다.
- **when**: `subscribeSse`로 구독한 뒤 `step`, `done` 이벤트를 순서대로 발생시킨다.
- **then**:
  - `onEvent`가 `step`, `done` 이벤트명과 JSON payload를 받는다.
  - `done` 이벤트 후 `onDone`이 호출된다.
  - EventSource가 close된다.

- **테스트 파일**: `frontend/__tests__/sse.test.ts`
- **테스트 이름**: `mock_refresh_stream_returns_sse_payload`
- **given**: MSW handler가 등록되어 있다.
- **when**: `GET /api/refresh-stream`을 fetch한다.
- **then**:
  - 응답 content-type이 `text/event-stream`이다.
  - 본문에 `event: step`, `event: done`이 포함된다.

## 구현 힌트

- `subscribeSse<T>(url, handlers)`는 브라우저 내장 `EventSource`만 사용한다.
- 이름 있는 이벤트는 `step`, `warn`, `token`, `done`, `error`만 등록한다.
- 이벤트 data는 JSON으로 파싱해 `handlers.onEvent(eventName, data)`로 넘긴다.
- `done` 또는 이름 있는 `error` 이벤트를 받으면 EventSource를 닫는다.
- `EventSource.onerror`가 발생하면 `handlers.onError?.(err)` 호출 후 닫는다.
- MSW refresh-stream handler는 작은 `text/event-stream` 응답을 반환한다. 실제 진행률 UI는 FE-007에서 사용한다.

## 결정 완료 테스트 명세

- **테스트 이름**: `sse_helper_dispatches_step_done_and_error_events`
- **fixture**: fake EventSource가 `step`, `done`, `error` event를 순서대로 발생시킨다.
- **action**: SSE helper를 connect한 뒤 fake event를 dispatch한다.
- **assertions**:
  - step callback이 progress payload를 받는다.
  - done callback 호출 후 connection close가 실행된다.
  - error event는 error callback으로 전달된다.
- **mock strategy**: 브라우저 EventSource를 fake class로 대체한다. 실제 SSE endpoint는 호출하지 않는다.
- **out of scope**: 홈 로딩 화면 UI와 refresh-stream 통합은 후속 step에서 구현한다.
