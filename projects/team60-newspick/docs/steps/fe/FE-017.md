# FE-017 - InlineQuiz 기본 렌더링

## 목표
기사 상세에 삽입할 O/X 퀴즈 컴포넌트의 기본 질문과 선택 버튼을 만든다.

## 사전 조건
- 같은 트랙 선행 step: FE-015 완료. FE-016 live integration gate는 BE/AI 준비 후 별도로 검증한다.
- mockable 외부 의존성: BE-013, AI-015. 미완료 상태에서도 MSW 또는 fixture로 진행한다.
- hard 외부 의존성 없음.

## Prototype 기준
- 1차 기준: `prototype/index.html`의 `.inline-quiz#inlineQuiz`.
- 스타일 기준: `prototype/styles.css`의 `.inline-quiz`, `.quiz-dots`, `.question-block`, `.ox-actions`.
- 보조 색인: `docs/design.md` §4.6, §5.1, §5.4. 충돌 시 원본 prototype을 따른다.
- 질문 라벨, O/X 버튼 구조, 카드 radius, border, gradient, spacing을 prototype과 동일하게 맞춘다.

## 파일 대상
```text
[신규] frontend/src/components/InlineQuiz.tsx

```

## 테스트 명세
- **테스트 파일**: `frontend/src/components/InlineQuiz.test.tsx`
- **테스트 이름**: `inline_quiz_renders_question_and_ox_buttons`
- **fixture**: quiz fixture `{id:"quiz_001", question:"이 기사는 AI를 다룬다", answer:true, explanation:"본문 근거"}`를 사용한다.
- **action**: `InlineQuiz`에 fixture를 props로 전달한다.
- **assertions**:
  - heading role 이름이 `이 기사는 AI를 다룬다`를 포함한다.
  - button role 이름 `O`와 `X`가 각각 있다.
  - 초기에는 `정답입니다` 또는 `아쉽습니다` 문구가 없다.
- **mock strategy**: 컴포넌트 단위 테스트만 사용한다. API 호출은 하지 않는다.
- **out of scope**: 상세 페이지 삽입과 결과 저장은 후속 step에서 구현한다.

## 구현 기준
- 선택 전 버튼은 둘 다 enabled 상태다.
- 질문 id는 aria-describedby 연결에 사용한다.

## 검증 방법
`cd frontend; pnpm test -- InlineQuiz.test.tsx`
`cd frontend; pnpm lint`

- prototype `.inline-quiz#inlineQuiz`와 구현 컴포넌트를 나란히 비교한다.
- 질문 라벨, 질문 본문, O/X 버튼 크기와 간격이 prototype과 같다.
- 카드 배경, border, radius, shadow, 내부 padding이 prototype과 같다.
