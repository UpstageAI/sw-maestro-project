# FE-035 - Chat error/reset state

## 목표
chat-stream 실패 시 에러 메시지와 새 대화 reset을 제공한다.

## 사전 조건
- 같은 트랙 선행 step: FE-034 완료.
- mockable 외부 의존성: BE-021, AI-027. 미완료 상태에서도 MSW 또는 fixture로 진행한다.
- hard 외부 의존성 없음.

## Prototype 기준
- 1차 기준: `prototype/index.html`의 `.app-page.chat-page`.
- 스타일 기준: `prototype/styles.css`의 `.chat-bubble--ai`, `.chat-reset-btn`, `.chat-input-bar`.
- 인터랙션 기준: `prototype/script.js`의 reset button과 intro/messages 전환 흐름.
- 보조 색인: `docs/design.md` §4.8, §6. 충돌 시 원본 prototype을 따른다.
- error/reset 상태도 prototype의 chat shell 구조, spacing, button tone을 유지한다.

## 테스트 명세
- **테스트 파일**: `frontend/src/features/chat/ChatShell.test.tsx`
- **테스트 이름**: `chat_stream_error_shows_alert_and_reset_button`
- **fixture**: fake stream이 `error` event data `{code:"CHAT_STREAM_FAILED", message:"답변 생성 실패"}`를 보낸다.
- **action**: 메시지를 submit한 뒤 error event를 발생시킨다.
- **assertions**:
  - role `alert`에 `답변 생성 실패`가 보인다.
  - button role 이름 `새 대화`가 보인다.
  - `새 대화` 클릭 후 메시지 목록이 비어 있다.
- **mock strategy**: EventSource adapter fake를 사용한다. 실제 서버는 호출하지 않는다.
- **out of scope**: 자동 재시도와 대화 저장은 범위 밖이다.

## 구현 기준
- error event는 assistant pending bubble을 제거한다.
- reset은 input value도 빈 문자열로 만든다.

`cd frontend; pnpm lint`

- prototype chat 화면과 구현 화면을 나란히 비교한다.
- error 후 pending bubble 제거, reset button, input 초기화 상태가 prototype shell 안에서 자연스럽게 유지된다.
- reset 후 intro/messages 전환이 prototype 동작과 같다.
