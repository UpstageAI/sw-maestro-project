# FE-021 - 상세 페이지에 InlineQuiz 삽입

## 목표
기사 상세 응답의 quiz 배열을 InlineQuiz에 연결한다.

## 사전 조건
- 같은 트랙 선행 step: FE-020 완료.
- mockable 외부 의존성: BE-013, AI-015. 미완료 상태에서도 MSW 또는 fixture로 진행한다.
- hard 외부 의존성 없음.

## Prototype 기준
- 1차 기준: `prototype/index.html`의 `.app-page[data-page="detail"]` 안 `.inline-quiz#inlineQuiz`.
- 스타일 기준: `prototype/styles.css`의 `.detail-article`, `.inline-quiz`, `.detail-quiz-button`.
- 인터랙션 기준: `prototype/script.js`의 inline quiz 흐름.
- 보조 색인: `docs/design.md` §4.5, §4.6. 충돌 시 원본 prototype을 따른다.
- 상세 본문 아래 퀴즈 삽입 위치, section 간격, 카드 폭과 여백을 prototype과 동일하게 맞춘다.

## 테스트 명세
- **테스트 파일**: `frontend/src/pages/ArticleDetailPage.test.tsx`
- **테스트 이름**: `article_detail_page_embeds_inline_quiz_when_quizzes_exist`
- **fixture**: detail fixture `article_001`에 quiz 2개를 포함한다. 첫 질문은 `본문 내용은 사실이다`이다.
- **action**: `/articles/article_001` 상세 페이지를 렌더링한다.
- **assertions**:
  - section accessible name `OX 퀴즈`가 보인다.
  - heading `본문 내용은 사실이다`가 보인다.
  - button `O`와 `X`가 보인다.
- **mock strategy**: MSW detail handler에 quiz 배열을 포함한다. 실제 BE/AI 서버는 호출하지 않는다.
- **out of scope**: quiz가 없는 기사 추천 UI는 이 단계에서 만들지 않는다.

## 구현 기준
- quiz 배열이 비어 있으면 섹션을 렌더링하지 않는다.
- 상세 본문과 퀴즈 사이 여백은 기존 spacing token을 사용한다.

## 검증 방법
`cd frontend; pnpm test -- ArticleDetailPage.test.tsx InlineQuiz.test.tsx`
`cd frontend; pnpm lint`

## 수동 브라우저 검증
- /articles/article_001에서 본문 아래 `OX 퀴즈` 섹션과 첫 질문이 보인다.
- prototype 상세 화면과 구현 화면을 나란히 비교해 본문, 퀴즈 카드, CTA 간격이 같다.
- 퀴즈 카드의 배경, border, radius, shadow, 내부 padding이 prototype과 같다.
