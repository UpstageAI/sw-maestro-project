# FE-022 - Quiz live integration gate

## 목표
상세 페이지 quiz 계약을 fixture 기반으로 검증하고, 실제 서버 호출은 live mode에서만 수행한다.

## 사전 조건
- 같은 트랙 선행 step: FE-021 완료.
- mockable 외부 의존성 없음.
- hard 외부 의존성: BE-014, AI-017. 미완료 상태에서는 구현 전에 중단한다.

## Prototype 기준
- 1차 기준: `prototype/index.html`의 `.app-page[data-page="detail"]` 안 `.inline-quiz#inlineQuiz`.
- 스타일 기준: `prototype/styles.css`의 `.inline-quiz`, `.quiz-dots`, `.ox-actions`, `.quiz-feedback`, `.quiz-result-summary`.
- 인터랙션 기준: `prototype/script.js`의 `renderQuizQuestion`, `showQuizResult`, `resetInlineQuiz`.
- 보조 색인: `docs/design.md` §4.5, §4.6, §6. 충돌 시 원본 prototype을 따른다.
- fixture와 live 응답 모두 prototype의 상세 화면 퀴즈 구조와 시각 상태를 동일하게 렌더링해야 한다.

## 파일 대상
```text
[신규] frontend/src/contracts/article-quiz.contract.test.ts
[수정] frontend/src/mocks/fixtures/articles.ts
```

## 테스트 명세
- **테스트 파일**: `frontend/src/contracts/article-quiz.contract.test.ts`
- **테스트 이름**: `article_quiz_contract_fixture_renders_inline_quiz`
- **fixture**: `article_001.detail-with-quiz.json` fixture는 quiz 배열 2개와 각 item의 `id`, `question`, `answer`, `explanation`을 가진다.
- **action**: 기본 테스트는 fixture schema와 상세 페이지 렌더링을 검증한다. `RUN_LIVE_CONTRACT=true`일 때만 live `/api/articles/article_001`을 호출한다.
- **assertions**:
  - 기본 `pnpm test`는 실제 서버 없이 통과한다.
  - fixture 기반 화면에 `OX 퀴즈`와 `O`/`X` button이 보인다.
  - live 응답 quiz item마다 required field 4개가 존재한다.
- **mock strategy**: 기본은 MSW fixture와 JSON schema validator다. live mode는 명시적 환경 변수에서만 실제 서버를 호출한다.
- **out of scope**: BE-014 또는 AI-017이 미완료이면 live mode와 이 step 구현은 진행하지 않는다.

## 구현 기준
- hard dependency `BE-014`, `AI-017` 완료 전에는 구현 전에 중단한다.
- live 준비 조건: FE `http://localhost:3000`, BE `http://localhost:8080`, AI `http://localhost:8000`, seeded quiz `quiz_001`.
- 실패 기준: quiz 배열 누락, answer boolean 아님, O/X button 미표시.

## 검증 방법
`cd frontend; pnpm test -- article-quiz.contract.test.ts`
`cd frontend; pnpm lint`
`RUN_LIVE_CONTRACT=true pnpm test -- article-quiz.contract.test.ts`

- prototype 상세 화면과 구현 화면을 나란히 비교한다.
- 질문, O/X 선택, feedback, 다음 문항, 결과 요약의 상태 전환이 prototype과 같다.
