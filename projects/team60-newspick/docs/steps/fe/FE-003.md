# FE-003 - Category Selection

## 목표

사용자가 카테고리 선택 페이지에서 관심 뉴스 분야를 선택하거나 해제할 수 있고, 선택 상태가 Zustand store에 반영된다.

## 사전 조건

- BOOT-000 완료
- FE-001 완료
- FE-002 완료
- `frontend/`에서 Vitest + Testing Library 테스트가 동작한다.

## 테스트 명세

- **테스트 파일**: `frontend/__tests__/category-store.test.ts`
- **테스트 이름**: `toggle_category_updates_selected_categories`
- **given**: `useCategoryStore` 초기 selected가 빈 배열
- **when**: `toggle("tech")`를 호출하고 다시 `toggle("tech")`를 호출
- **then**: 첫 호출 후 `["tech"]`, 두 번째 호출 후 `[]`

- **테스트 파일**: `frontend/__tests__/category-page.test.tsx`
- **테스트 이름**: `renders_and_toggles_category_cards`
- **given**: `/onboarding/category` 페이지 컴포넌트
- **when**: Testing Library로 렌더링하고 `테크` 카테고리를 클릭
- **then**:
  - heading `관심 있는 뉴스를 골라주세요`가 보인다.
  - `테크`, `경제`, `정책`, `이슈` 카테고리가 보인다.
  - `테크` 버튼의 `aria-pressed`가 클릭 전 `false`, 클릭 후 `true`가 된다.

## 구현 힌트

- `/onboarding/category`는 상호작용이 있으므로 Client Component로 만든다.
- `frontend/lib/store/category.ts`에 `useCategoryStore`를 만든다.
- store 상태는 `{ selected: string[], toggle: (category: string) => void, reset: () => void }` 정도로 유지한다.
- 이번 step에서는 선택 완료 후 feed 이동을 구현하지 않는다. 다음 흐름은 이후 step에서 연결한다.
- 스플래시 CTA는 `Link`로 `/onboarding/category`에 연결한다.
- 카테고리 카드는 `aria-pressed`를 가진 `button`으로 구현한다.

## 결정 완료 테스트 명세

- **테스트 이름**: `category_page_toggles_selected_categories_in_store`
- **fixture**: category fixture `정치`, `경제`, `테크` 3개와 빈 Zustand store.
- **action**: 카테고리 버튼 `테크`를 클릭한 뒤 다시 클릭한다.
- **assertions**:
  - 첫 클릭 후 `테크` button의 selected state가 true다.
  - store selectedCategories에 `테크`가 포함된다.
  - 두 번째 클릭 후 selected state가 false다.
- **mock strategy**: API mock은 사용하지 않는다. Zustand store를 테스트마다 초기화한다.
- **out of scope**: 카테고리별 실제 API 필터링은 구현하지 않는다.
