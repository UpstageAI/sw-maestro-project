# FE-037 - Chat live integration gate

## 목표
실제 chat-stream 계약을 hard-gated live mode에서 검증한다.

## 사전 조건
- 같은 트랙 선행 step: FE-036 완료.
- mockable 외부 의존성 없음.
- hard 외부 의존성: BE-023, AI-029. 미완료 상태에서는 구현 전에 중단한다.

## Prototype 기준
- 1차 기준: `prototype/index.html`의 `.app-page.chat-page`.
- 스타일 기준: `prototype/styles.css`의 `.chat-header`, `.chat-messages`, `.chat-bubble--ai`, `.chat-typing`, `.chat-article-card`, `.chat-input-bar`.
- 인터랙션 기준: `prototype/script.js`의 full chat response flow.
- 보조 색인: `docs/design.md` §4.8, §5.2, §6. 충돌 시 원본 prototype을 따른다.
- fixture와 live stream 모두 token bubble, done article card, error state, reset state를 prototype과 동일하게 렌더링해야 한다.

## 테스트 명세
- **테스트 파일**: `frontend/src/contracts/chat-stream.contract.test.ts`
- **테스트 이름**: `chat_stream_contract_fixture_and_live_mode_use_article_card_summary`
- **fixture**: fixture stream은 `token` 2개와 `done` `{articles:[ArticleCardSummary]}`를 포함한다. `ArticleCardSummary` 필수 필드는 `id`, `title`, `source`, `publishedAt`이다.
- **action**: 기본 테스트는 fixture stream을 파싱하고 UI에 token bubble과 참고 기사 card를 렌더링한다. `RUN_LIVE_CONTRACT=true`일 때만 실제 `/api/chat-stream`을 호출한다.
- **assertions**:
  - 기본 `pnpm test`는 실제 서버 없이 통과한다.
  - fixture 기반 assistant bubble text가 누적된다.
  - done article card가 schema required field 4개를 모두 가진다.
  - live mode에서 token event 1개 이상과 done event 1개가 순서대로 도착한다.
- **mock strategy**: 기본은 fake EventSource와 JSON schema validator다. live mode는 `RUN_LIVE_CONTRACT=true`에서만 실제 서버를 호출한다.
- **out of scope**: BE-023 또는 AI-029가 미완료이면 구현 전에 중단한다.

## 구현 기준
- hard dependency `BE-023`, `AI-029` 완료 전에는 이 step을 진행하지 않는다.
- live 준비 조건: FE `http://localhost:3000`, BE `http://localhost:8080`, AI `http://localhost:8000`, article seed 최소 3건.
- 실패 기준: token 미수신, done 누락, ArticleCardSummary 필수 필드 누락, SSE 연결 10초 초과.

## 검증 방법

`cd frontend; pnpm lint`
`RUN_LIVE_CONTRACT=true pnpm test -- chat-stream.contract.test.ts`
