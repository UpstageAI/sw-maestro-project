# BE-002 - Article 엔티티와 Repository 작성

## 목표
`articles` 테이블을 JPA 엔티티와 repository로 접근할 수 있게 한다. 이 단계는 API를 열지 않고 저장과 단건 조회만 다룬다.

## 사전 조건
- `BE-001`의 Flyway V1 migration이 통과한다.
- `docs/contracts/db-init.sql`의 `articles` 컬럼명을 그대로 사용한다.

## 파일 대상
```text
[신규] backend/src/main/java/com/newspick/article/Article.java
[신규] backend/src/main/java/com/newspick/article/ArticleRepository.java
[신규] backend/src/test/java/com/newspick/article/ArticleRepositoryTest.java
```

## 테스트 명세
- **테스트 파일**: `backend/src/test/java/com/newspick/article/ArticleRepositoryTest.java`
- **테스트 이름**: `save_then_findById_returns_article`
- **fixture**: `article_001` id, `https://example.com/a1` url, title `첫 기사`, source `Example`, category `tech`, `publishedAt=2026-05-01T09:00:00Z`, status `summarized`를 가진 Article 객체.
- **action**: Testcontainers PostgreSQL에 Article을 저장한 뒤 `findById("article_001")`를 호출한다.
- **assertions**:
  - 조회 결과가 존재한다.
  - `title`, `source`, `category`, `status`가 fixture 값과 같다.
  - `publishedAt`은 UTC instant로 round-trip 된다.
- **mock strategy**: 외부 mock은 쓰지 않는다. `@DataJpaTest`와 Testcontainers PostgreSQL만 사용한다.
- **out of scope**: feed/detail HTTP API와 summary JSON 매핑은 이 단계에서 구현하지 않는다.

## 구현 기준
- `@Table(name = "articles")`와 명시적 컬럼 매핑을 사용한다.
- `id`는 문자열 primary key로 둔다.
- `summary`, `content`, `embedding`은 후속 AI 저장 단계에서 채우므로 nullable로 둔다.

## 검증 방법
`cd backend; ./gradlew test --tests "*ArticleRepositoryTest"`
