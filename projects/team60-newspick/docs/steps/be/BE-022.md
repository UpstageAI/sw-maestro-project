# BE-022 - chat request validation and context ids

## 목표
chat request의 message와 contextArticleIds validation을 고정한다.

## 사전 조건
- 같은 트랙 선행 step: BE-021 완료.
- mockable 외부 의존성: AI-024. 미완료 상태에서는 WireMock, fixture, repository mock으로 대체한다.
- hard 외부 의존성 없음.

## 파일 대상
```text
[수정] backend/src/main/java/com/newspick/chat/ChatRequest.java
[수정] backend/src/test/java/com/newspick/chat/ChatControllerTest.java
```

## 테스트 명세
- **테스트 파일**: `backend/src/test/java/com/newspick/chat/ChatControllerTest.java`
- **테스트 이름**: `chatStream_rejects_blank_message_and_accepts_context_article_ids`
- **fixture**: fixture request는 blank message와 valid request `{message:"요약해줘", contextArticleIds:["article_001"]}` 두 개이다.
- **action**: blank request와 valid request를 각각 `POST /api/chat-stream`로 보낸다.
- **assertions**:
  - blank request는 HTTP 400과 `INVALID_CHAT_MESSAGE` code를 반환한다.
  - valid request는 PythonChatClient에 `article_001`을 전달한다.
  - valid 응답은 SSE token을 반환한다.
- **mock strategy**: PythonChatClient mock을 사용한다. DB article existence 검증은 하지 않는다.
- **out of scope**: 추천 질문 생성은 FE-036 범위다.

## 구현 기준
- message trim 후 1자 이상, 500자 이하로 고정한다.
- contextArticleIds는 최대 5개로 고정한다.

## 검증 방법
`cd backend; ./gradlew test --tests "*ChatControllerTest"`
