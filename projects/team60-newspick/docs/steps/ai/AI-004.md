# AI-004 - LangGraph refresh skeleton과 state 정의

## 목표
refresh pipeline의 state shape와 최소 graph 실행 경로를 고정한다.

## 사전 조건
- `AI-003`의 embedding helper가 존재한다.
- `docs/architecture/pipeline-design.md`의 refresh graph 순서를 따른다.

## 파일 대상
```text
[신규] ai/src/newspick_ai/graph/state.py
[신규] ai/src/newspick_ai/graph/refresh_graph.py
[신규] ai/tests/test_refresh_graph.py
```

## 테스트 명세
- **테스트 파일**: `ai/tests/test_refresh_graph.py`
- **테스트 이름**: `refresh_graph_runs_collector_node_and_returns_state`
- **fixture**: Fake collector node가 `articles=[{id:"article_001", url:"https://example.com/a1", title:"첫 기사"}]`를 state에 추가한다.
- **action**: `build_refresh_graph(collector=fake_collector).ainvoke({articles: [], events: []})`를 실행한다.
- **assertions**:
  - 출력 state의 `articles[0].id`가 `article_001`이다.
  - 출력 state의 `events[0].stage`가 `collect`이다.
  - 입력 state에 없던 key를 만들 때 typed state 필드를 사용한다.
- **mock strategy**: collector node만 fake 함수로 주입한다. Solar, RSS, DB는 호출하지 않는다.
- **out of scope**: RSS 파싱, dedupe, persist, SSE 이벤트 변환은 후속 step에서 구현한다.

## 구현 기준
- state는 `TypedDict` 또는 Pydantic model 중 하나로 고정하고 테스트에서 타입을 import한다.
- graph node 이름은 `collect`로 둔다.
- event shape는 `{stage, message, articleIds}`를 사용한다.

## 검증 방법
`cd ai; uv run pytest ai/tests/test_refresh_graph.py`
