# AI-008 - Persistor 노드 DB INSERT

## 목표
refresh graph의 article 후보를 PostgreSQL `articles` 테이블에 저장한다.

## 사전 조건
- `AI-007`의 SSE endpoint가 fake runner로 동작한다.
- `docs/contracts/db-init.sql`의 `articles` schema를 따른다.

## 파일 대상
```text
[신규] ai/src/newspick_ai/graph/persistor.py
[신규] ai/tests/test_persistor.py
```

## 테스트 명세
- **테스트 파일**: `ai/tests/test_persistor.py`
- **테스트 이름**: `persistor_inserts_one_empty_article_row`
- **fixture**: Testcontainers PostgreSQL에 `docs/contracts/db-init.sql`을 적용하고 state articles에 `article_001`, url, title, source, category, publishedAt, status `collected`를 넣는다.
- **action**: `Persistor(asyncpg_pool).run(state)`를 실행한 뒤 `SELECT id, url, status FROM articles WHERE id=$1`을 조회한다.
- **assertions**:
  - DB row가 1건 존재한다.
  - `id`가 `article_001`이다.
  - `status`가 `collected`이다.
  - 출력 event stage가 `persist`이고 count가 `1`이다.
- **mock strategy**: DB는 fake로 대체하지 않는다. Testcontainers PostgreSQL과 asyncpg를 사용한다. Solar와 RSS는 호출하지 않는다.
- **out of scope**: summary, embedding, quiz, daily_report 저장은 후속 M3~M5 step에서 구현한다.

## 구현 기준
- 중복 URL insert는 `ON CONFLICT (url) DO NOTHING`으로 고정한다.
- connection string은 `DATABASE_URL`로 읽는다.
- created_at/updated_at은 DB default를 사용한다.

## 검증 방법
`cd ai; uv run pytest ai/tests/test_persistor.py`
