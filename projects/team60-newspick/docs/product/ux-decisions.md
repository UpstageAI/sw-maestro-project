# UI/UX 결정사항

## 현재 UI/UX 반영 상태

- 홈 피드는 RSS 기사 카드형 UI로 정리했다.
- 기사 카드는 카테고리, 출처, 발행 시간, 제목, AI 요약, 키워드, 상세 보기 버튼을 포함한다.
- 하단 네비게이션은 `홈`, `AI 챗(중앙 원형 버튼)`, `리포트` 3단 구조다.
- 퀴즈는 별도 네비게이션 탭이 아니라 기사 상세 안에 포함했다.
- 기사 상세는 `핵심만 보기`, `왜 중요해?`, `조금 더 알기`, `O/X 퀴즈` 흐름으로 구성했다.
- O/X 퀴즈는 3문항 진행, 즉시 피드백, 완료 후 결과 요약을 제공한다.
- 데일리 리포트 화면을 C+ 보강형(타임라인 메타포)으로 재설계했다. 상단에 날짜·요일·업데이트 시각, AI 브리핑 카드(흰색 배경, ink 색상 본문) 순으로 두고, 본문은 vertical timeline 형태다. 가장 많이 다뤄진 이슈를 헤드라인 노드(큰 노드, 색상 ring 강조, 17px 본문, 매체 수 dots 시각화)로, 2~3위는 작은 노드 + 한 줄 카드로 표시한다. 그 아래 카테고리별 한 줄 정리(흐름) 리스트, 빈도 차등 키워드 클라우드(상위 키워드 17px → 하위 11px, 불투명도 차등), 마지막에 점선 디바이더 + 체크 + "내일 09:30에 다시 만나요" 미니멀 마침표를 둔다.
- 헤드라인은 임베딩 유사도 클러스터링으로 오늘 가장 많이 다뤄진 주제를 선정하며, 배지에는 해당 주제를 다룬 매체 수(출처 수 기준)를 표시한다.
- AI 어시스턴트 챗 화면을 추가했다. 초기 상태(안내 문구 + 제안 칩 4종), 대화 상태(사용자/AI 버블, 타이핑 인디케이터), 대화 초기화 버튼으로 구성된다.
- 홈 피드 뉴스는 실제 2025년 이슈 기반 예시(AI 에이전트 경쟁, 미국 관세 여파, 합계출산율 역대 최저)로 채웠다.

## 유지해도 좋은 방향

- `홈 -> 상세 -> 상세 안 퀴즈` 흐름은 기획서와 잘 맞는다.
- 별도 퀴즈 탭을 제거한 판단은 적절하다. 퀴즈는 기사에 종속된 기능이기 때문이다.
- 상세 페이지에서 원문 기반 AI 정리임을 보여주는 구조는 유지하는 것이 좋다.
- 데일리 리포트는 MVP 범위와 맞으므로 네비게이션에 남겨두는 것이 좋다.
- AI 챗은 시연용으로 충분히 가치 있는 기능이며 RAG 구조의 핵심 경험이다.

## 남은 수정사항

### 1. O/X 퀴즈 결과 개선

현재 결과 요약은 기본 형태다. 추후에는 다음을 추가하면 좋다.

- 다시 풀기
- 다른 기사 보기
- 리포트에 반영됨 안내
- 오답 문항만 다시 보기

### 2. 빈 상태와 로딩 상태 보강

실제 RSS 수집에서는 기사 없음, 로딩 중, 실패 상태가 자주 발생한다.

필요한 상태:

- 선택 카테고리에 새 기사가 없음
- 오늘 기사 수집 중
- RSS 연결 실패
- AI 요약 대기 중

#### 홈 로딩 화면 — 실제 진행률 기반 (구현 완료)

기존 "관심 카테고리 확인 / 주요 뉴스 수집 / AI 요약 생성" 3단계 텍스트는 백엔드와 무관한 연출이라 제거했다. 대신 두 단계만 남기고 카운터 + 진행 바를 통해 실제 처리량을 노출한다.

- **주요 뉴스 수집**: `N / 12 매체` 카운터 + 진행 바. Collector → Deduplicator 노드 진행에 매핑.
- **AI 요약 생성**: `N / 8 기사` 카운터 + 진행 바. ArticleExtractor → Summarizer → SummaryValidator 노드 진행에 매핑.

현재 프론트는 ease-out cubic 애니메이션으로 진행률을 mock하지만, 실제 구현 시에는 백엔드 SSE/WebSocket 이벤트를 받아 카운터를 갱신해야 한다.

권장 이벤트 형태:

```
event: step  data: {"step": "collect", "current": 7, "total": 12}
event: step  data: {"step": "collect", "current": 12, "total": 12}
event: step  data: {"step": "summarize", "current": 3, "total": 8}
event: done  data: {"articles": [...]}
```

LangGraph의 `astream_events`로 노드 진입/종료 이벤트를 받아 그대로 SSE로 흘리는 방식을 권장한다. 카테고리 확인 단계는 즉시 끝나는 DB 조회라 UI에 노출하지 않는다.

> 실제 SSE 스키마와 LangGraph 연동 코드는 [architecture/realtime-ui-states.md](../architecture/realtime-ui-states.md) 참조.
