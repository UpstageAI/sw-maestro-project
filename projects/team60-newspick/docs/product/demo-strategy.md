# 발표 시연 전략

프로젝트 성격상 실시간 데이터 수집보다 안정적인 시연이 중요하다.

## 챗봇 데이터 전략

발표 당일 라이브 파이프라인 실행은 API 실패·타임아웃 위험이 있어 권장하지 않는다. 다음 방식을 사용한다.

1. 발표 1~2일 전에 LangGraph 파이프라인을 1회 실행해 기사 20~30건을 수집·요약·임베딩까지 완료한다.
2. 해당 결과를 DB에 고정한다 (이후 추가 수집 없음).
3. 발표 중 챗봇은 고정 DB에 대해 벡터 검색만 수행한다.

이렇게 하면 실제 AI 파이프라인 결과를 사용하면서 발표 중 장애 리스크를 없앨 수 있다.

## 시연 시나리오 준비

DB에 없는 내용에 대한 질문이 들어올 경우 엉뚱한 답이 나올 수 있다. 발표 전 다음을 준비한다.

- 시연 질문 3~4개를 미리 정해두고 해당 기사가 DB에 있는지 확인한다.
- 질문 예시: "오늘 AI 관련 뉴스 뭐 있어?", "경제 흐름 정리해줘", "오픈AI 최근 동향은?"

> RAG 챗 에이전트의 발표 시연 운영 지침은 [ai/rag-chat.md](../ai/rag-chat.md) 의 "발표 시연 전략" 섹션도 참고.
